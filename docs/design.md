中文离线宝可梦图鉴 UI/UX 设计文档

1. 设计目标

本应用定位为：

«简洁、现代、信息密度适中、适合长期查询使用的中文离线宝可梦图鉴。»

设计不能做成普通“数据库管理应用”，也不要做成花哨的游戏界面。

核心体验：

打开快 → 搜索快 → 找到快 → 信息容易读 → 关联资料容易继续查。

设计优先级：

查询效率
> 信息层级
> 阅读舒适度
> 宝可梦视觉特色
> 动画效果

---

2. 总体设计方向

采用：

Material 3 基础规范 + 宝可梦属性视觉语言 + 卡片式信息布局。

不要直接照搬 Pokédex 红色机器外观。

整体应该更接近现代资料应用。

视觉关键词：

清爽
圆润
轻量
现代
克制
高可读性
有宝可梦特色

避免：

大量高饱和红色
大面积渐变
复杂背景纹理
过度阴影
大量描边
过度动画
拟物 Pokédex
游戏 UI 式按钮堆叠

---

3. 色彩系统

3.1 基础界面

主体背景保持中性。

浅色模式：

背景：接近白色
卡片：白色或轻微灰色
一级文字：深灰
二级文字：中灰
分隔区域：浅灰

深色模式：

背景：深灰黑
卡片：略亮于背景
一级文字：接近白色
二级文字：灰色

不要使用纯黑配纯白造成过强对比。

---

4. 属性色是核心视觉识别

不同属性使用固定颜色。

例如：

一般    灰
火      红橙
水      蓝
电      黄
草      绿
冰      浅蓝
格斗    深红
毒      紫
地面    土黄
飞行    蓝紫
超能力  粉
虫      黄绿
岩石    棕
幽灵    深紫
龙      紫蓝
恶      深灰
钢      蓝灰
妖精    粉红

属性颜色主要用于：

- 属性标签
- 宝可梦详情页局部强调
- 属性克制
- 图表
- 小面积背景装饰

禁止将整个页面大面积涂成属性色。

原则：

«属性色负责识别，不负责填满页面。»

---

5. 双属性颜色

例如：

妙蛙种子
草 / 毒

不要制作大面积绿色→紫色渐变。

优先使用两个独立属性标签：

[ 草 ] [ 毒 ]

如果详情页顶部需要体现双属性，可以使用非常轻微的双色视觉元素。

---

6. 字体与数字

中文使用系统字体。

不要额外内置大型字体文件增加 APK 体积。

层级建议：

页面标题      22–24sp
宝可梦名称    24–28sp
区块标题      18–20sp
正文          14–16sp
辅助信息      12–14sp

全国图鉴编号使用弱化颜色：

#0445
烈咬陆鲨

视觉重点应该是“烈咬陆鲨”，而不是 "#0445"。

---

7. 圆角

统一圆角体系。

建议：

大卡片：16dp
小卡片：12dp
标签：完全圆角或 8–12dp
搜索框：20–28dp

不要每个组件使用不同圆角。

---

8. 阴影

尽量少用明显阴影。

通过：

背景层级
卡片颜色
间距

区分内容。

深色模式尤其避免明显阴影。

---

9. 应用整体导航

建议底部导航栏保持 4 个一级入口：

图鉴
搜索
收藏
设置

不要把“首页”和“图鉴”同时做成两个功能高度重复的入口。

默认启动：

图鉴

---

10. 图鉴主页

这是用户打开应用后最常看到的页面。

顶部：

[全部] [第一世代] [第二世代] ...

不要先展示：

新闻
推荐内容

这些会降低查询效率。

11. 搜索框

搜索框是核心组件。

位置：

视觉：

│ 🔍 搜索宝可梦、编号、招式…… │
└─────────────────────────────┘

12. 图鉴列表

默认建议使用：

双列卡片。

例如：

┌──────────────┐ ┌──────────────┐
│ #0001        │ │ #0004        │
│              │ │              │
│   妙蛙种子   │ │    小火龙    │
│    图片      │ │     图片     │
│              │ │              │
│ [草] [毒]    │ │    [火]      │
└──────────────┘ └──────────────┘

卡片信息严格控制。

只显示：

- 编号
- 图片

- 属性

不要在列表卡片里显示：

- 身高
- 体重
- 特性
- 种族值
- 世代说明

这些属于详情页。

39. 深色模式

必须从第一阶段考虑。

不能开发完浅色模式后简单反转颜色。

重点检查：

- 属性标签
- 种族值图
- 卡片
- 搜索框
- 底部抽屉
- 图片背景
- 分割线

40. 动画原则

动画应该服务于空间关系。

可以使用：

页面进入

轻微淡入/位移。

宝可梦卡片 → 详情

图片可以考虑共享元素过渡。

收藏

轻微缩放反馈。

形态切换

图片淡入淡出。

筛选面板

标准底部抽屉动画。

禁止：

- 大幅弹跳
- 页面旋转
- 长时间入场动画
- 每张卡片依次出现
- 大量粒子效果

原则：

«用户连续查询时，动画不能成为等待。»

---

41. 触觉反馈

可以在以下操作提供轻微触觉：

- 收藏
- 取消收藏
- 筛选确认

普通滚动、打开页面不要频繁振动。

---

42. 返回行为

遵循安卓标准。

例如：

图鉴
 ↓
烈咬陆鲨
 ↓
粗糙皮肤

返回：

粗糙皮肤
→ 烈咬陆鲨
→ 图鉴原滚动位置

返回图鉴时必须尽量恢复：

- 原滚动位置
- 原筛选条件
- 原搜索状态

不能每次返回都重新回到 #0001。

---

43. 加载状态

因为主要数据离线：

核心资料页面原则上不应该出现长时间加载动画。

数据库查询短暂等待可以使用骨架或轻量占位。

不要到处显示转圈。

---

44. 图片加载失败

图片不可用时：

显示统一占位图。

仍然正常展示：

名称
编号
属性
资料

图片加载失败不能导致详情页无法使用。

---

45. 空状态

收藏为空：

还没有收藏宝可梦

在宝可梦详情页点击 ☆ 即可收藏。

不要使用大段解释。

---

46. 错误提示

面向用户使用自然语言。

例如：

图片加载失败

而不是：

HTTP 404
CoilException
Network Error

技术错误写入日志。

---

47. 横屏与平板

第一阶段以手机竖屏为主。

但是布局不能硬编码固定宽度。

平板后续可以采用双栏：

┌───────────────┬────────────────────┐
│               │                    │
│ 宝可梦列表     │ 宝可梦详情          │
│               │                    │
│               │                    │
└───────────────┴────────────────────┘

第一阶段不要求完成平板专属界面，但架构不能阻碍后续实现。

---

48. 无障碍

必须注意：

- 不仅依靠颜色表达属性和倍率
- 属性标签必须有文字
- 图标提供语义描述
- 点击区域足够大
- 文字支持系统字体缩放
- 深浅模式保持合理对比度

例如不能只用：

红色 = 弱点
绿色 = 抵抗

必须同时显示：

2×
½×

---

49. 页面信息密度原则

图鉴属于资料工具，因此允许比普通消费应用更高的信息密度。

但必须遵循：

概览
↓
核心数据
↓
详细资料
↓
关联资料

不能把所有字段平铺。

---

53. 图标原则

优先使用 Material Symbols。

只有宝可梦属性图标等具有实际识别价值的内容才使用自定义资源。

不要大量使用来源不统一的图标包。

---

54. 交互反馈

所有可点击元素必须有明确反馈：

点击态
水波纹
颜色变化
轻微状态变化

用户不能需要猜测某个文字是否可以点击。

---

55. 关键用户路径

路径 A：查某只宝可梦

目标：

3 次操作以内看到详情。

打开应用
→ 搜索
→ 输入“烈咬”
→ 烈咬陆鲨详情

---

路径 B：浏览全国图鉴

打开应用
→ 上下滚动
→ 点击宝可梦
→ 详情

无需进入多级菜单。

---

路径 C：查属性弱点

搜索宝可梦
→ 详情
→ 属性克制

核心倍率应该在详情页直接看到。

---

路径 D：查招式

搜索
→ 输入“十万伏特”
→ 招式详情

不能要求：

首页
→ 更多
→ 数据库
→ 招式
→ 搜索

---

路径 E：连续查询

烈咬陆鲨
→ 粗糙皮肤
→ 拥有该特性的宝可梦
→ 鲨丘龙

关联资料都应该可点击。

这是图鉴应用的重要体验。

56. 第一阶段视觉优先级

必须优先精细设计：

1. 宝可梦卡片
2. 搜索
3. 宝可梦详情顶部
4. 属性标签
5. 种族值
6. 属性克制
7. 进化链
8. 招式列表

设置页等使用标准 Material 3 即可。

不要平均分配设计时间。

---

57. 禁止出现的设计问题

OMP 实现 UI 时重点避免：

1. 卡片套卡片

例如：

大卡片
 └─ 基本信息卡片
     └─ 身高卡片

禁止。

2. 所有内容都做卡片

普通文本和列表不需要全部套 Card。

3. 大面积属性渐变背景

影响阅读。

4. 首页塞满入口

核心就是“图鉴 + 搜索”。

5. 过度圆角

避免所有东西都像胶囊。

6. 信息重复

详情顶部已经显示：

烈咬陆鲨
龙 / 地面

下面基本信息不要再次重复。

7. 英文优先

这是中文应用。

中文名称必须是主要视觉名称。

英文属于辅助资料。

8. 隐藏核心功能

搜索、筛选、收藏不能藏进三级菜单。

9. 为了动画牺牲速度

离线图鉴应该给人“立即出现”的感觉。

58. 推荐的整体视觉结构

最终希望形成这种视觉逻辑：

                    中文离线宝可梦图鉴

                          │
        ┌─────────────────┴────────────────┐
        │                                  │
      浏览                               搜索
        │                                  │
   双列图鉴卡片                      即时统一搜索
        │                                  │
        └──────────────┬───────────────────┘
                       │
                  宝可梦详情
                       │
        ┌──────────────┼──────────────┐
        │              │              │
      核心资料       战斗资料        关联资料
        │              │              │
    基本信息         种族值          进化
    图鉴说明         属性克制        特性
                     招式            相关宝可梦

整体体验应该让用户感觉：

«这是一款为“查宝可梦资料”专门设计的工具，而不是套用了宝可梦数据的通用 Material 3 演示应用。»

59. OMP 实现 UI 前的要求

不要收到本文档后直接一次性编写全部界面。

首先：

1. 阅读开发需求文档。
2. 检查当前项目已有界面。
3. 确认 Material 3 版本和 Compose 架构。
4. 建立统一颜色、字号、间距、圆角规范。
5. 建立属性颜色系统。
6. 建立核心通用组件。
7. 先实现图鉴主页静态原型。
8. 再实现宝可梦详情静态原型。
9. 检查浅色/深色模式。
10. 确认视觉方案后再接真实数据。

不要一开始把数据库、业务逻辑和 UI 全部混在一起开发。

第一轮只需要实现：

页面 1：图鉴主页

- 世代筛选

61. UI 验收标准

第一轮 UI 完成后必须检查：

- 搜索是否始终容易找到
- 中文名称是否为视觉主体
- 属性是否容易识别
- 卡片信息是否过载
- 详情页是否存在明显重复信息
- 种族值是否容易比较
- 属性克制倍率是否一眼可读
- 进化关系是否清晰
- 招式列表是否适合快速扫描
- 页面是否存在卡片套卡片
- 是否存在无意义的大面积留白
- 深色模式是否正常
- 系统字体放大后是否严重错位
- 返回列表是否保留位置
- 连续查询关联资料是否顺畅

如果上述核心问题没有解决，不进入视觉细节打磨阶段。

---

62. 最终设计原则

所有设计决策优先回答三个问题：

第一，这能不能让用户更快找到资料？

第二，这能不能让复杂的宝可梦数据更容易理解？

第三，这个视觉元素是否真的有必要？

如果答案都是否定的，则删除该元素。

最终目标不是“看起来功能很多”，而是：

«搜索极快、信息清楚、关联自然、离线可靠，并且具有足够的宝可梦视觉辨识度。»
